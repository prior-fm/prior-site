One point.

Read a photo’s pixels left to right, row by row, and the whole image becomes one point in n-dimensional space

A matrix, read row by row, becomes one long list — a vector with components x₁ through xₙ. If the image has n pixels, the image is a point in n-dimensional real space. Every number in the film is a real run on the film’s own photograph: the 9×12 grid it scans has exactly 108 cells, the full photo is a vector with 3,147,776 components, and the DOG 0.90 / TREE 0.30 boxes are a real object-detection model’s honest output, not set dressing. Nothing typed by hand.

The thing worth noticing
Distance
between
images is
a number.

Once an image is a point, the question “how similar are these two photos?” stops being philosophy and becomes geometry: it is the distance between two points. That single move — flatten, then measure — is the quiet foundation under image search, face unlock, recommendation feeds and every “find similar” button you have ever pressed. The pack computes one such distance in eight lines of Python, because seeing the number appear is what makes the idea land.

The film’s detection scene runs the argument forward: a model that labels a DOG at 0.90 confidence is doing geometry in exactly this kind of space — and the honest 0.30 it gives the tree is part of the lesson. Confidence is a position in space, not a promise.

The pack
Turn your
photos into
points

Both pipelines from the film: image → matrix → vector → point, and the real detector behind the boxes.

python vectorize.py your-photo.jpg prints the matrix, flattens it into the vector, names the space (Rⁿ with your photo’s real n), and measures one real distance between two images as points. python detect.py your-photo.jpg re-runs the film’s object detection on anything you give it — YOLOv8 on Open Images V7, the 600-class vocabulary that can actually label a tree — and draws the boxes with their honest confidences.
