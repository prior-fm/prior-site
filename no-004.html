Selection sort moves the same six numbers three times — on exactly the same fifteen comparisons

Five passes over [4, 6, 8, 5, 2, 1]. Each pass walks the unsorted run, compares neighbours, and swaps the pair whenever the left one is bigger — so the largest value alive bubbles to the end and settles there. Fifteen comparisons, eleven swaps, and after the fifth pass nothing is left to move.

The thing worth noticing
Comparisons
are cheap.
Writes are not.

Run the same array through selection sort and it does the same fifteen comparisons — but only three swaps. Bubble sort fixes every out-of-order pair the moment it meets one; selection sort scans the whole run, finds the smallest, and writes once. Same reading, a third of the writing. That gap is why selection sort still turns up where a write costs orders of magnitude more than a read — flash, EEPROM — despite both being O(n²).

It does not make selection sort faster in general, and the visualiser will show you why in about ten seconds: give both an already-sorted list. Bubble sort's swapped flag lets it exit after a single pass — five comparisons, no swaps. Selection sort has no early exit and grinds through all fifteen regardless. Neither one wins. They lose differently.
